# SaarAI meeting workspace

Date: 2026-09-06
Status: approved in brainstorming, awaiting spec review
Scope: sub-project 2 of 3 in the SaarAI frontend redesign. Depends on sub-project 1 (identity foundation), merged.

## Context

Sub-project 1 gave the app its identity: tokens, themes, the Thread status primitive, the icon rail, and the public pages. The four app pages that carry the product's value, Dashboard, Meetings, Meeting detail, and Transcript, were only restyled. This sub-project redesigns them.

Today a finished meeting shows a split view: transcript cards on the left, three markdown tabs on the right, generated by one blocking call to the `all` endpoint. The markdown comes from prompts that ask for emoji-prefixed h3 sections and GFM tables. Nothing links the outputs back to the transcript. In-progress meetings show only a status.

Decisions made during brainstorming:

- A finished meeting is optimised for reading the essence first; the transcript is evidence opened beside it.
- Essence items cite the transcript. This requires structured output from the generators, so the backend is in scope.
- The workspace follows a live meeting: the transcript grows while the bot is in the call.
- Essence generates automatically on first open of a finished meeting.
- The Dashboard becomes "today's desk": send a bot, what is live, what recently finished. Stat tiles go.
- Layout A: the essence reads as one scrolling document with a section nav; the transcript is a right-side drawer opened by citations.

## Design principles

- **Essence is the page.** The essence column is the main reading surface, capped at a comfortable measure. The transcript never competes for width; it slides in when asked for and slides away.
- **Every claim has a source.** A decision, action, insight, or risk carries a citation to the utterance it came from. Clicking it shows the words.
- **One page, five phases.** Live, processing, generating, ready, and failed are states of the same page, expressed by the Thread and by what fills the essence column. There is no separate transcript page.
- **Structure over prose.** Action items are a table with owners. Participation is a bar. Risks are a table. Markdown is only for legacy outputs.
- **Thread over badge.** Unchanged from sub-project 1. The Thread gains a `failed` state.

## Backend

All backend code lives in `saar_ai/app/`. The API base and auth stay as they are.

### Essence schemas (`app/schemas/essence.py`)

Pydantic models used both for structured LLM output and for API responses.

```
Cited            { text: str, refs: list[int] }          # refs are utterance indices
Action           { text: str, owner: str | None, due: str | None, refs: list[int] }
Participation    { name: str, share: float, note: str, refs: list[int] }   # share in [0, 1]
Priority         { action: str, owner: str | None, why: str, refs: list[int] }
Risk             { risk: str, likelihood: "low"|"medium"|"high", impact: "low"|"medium"|"high", mitigation: str, refs: list[int] }
Sentiment        { overall: "positive"|"neutral"|"tense", note: str }

Minutes   { summary: str, discussion: list[Cited], decisions: list[Cited], actions: list[Action], notes: list[Cited] }
Insights  { participation: list[Participation], themes: list[Cited], patterns: list[Cited], concerns: list[Cited], sentiment: Sentiment, takeaways: list[Cited] }
Strategy  { priorities: list[Priority], followups: list[Cited], resources: list[Cited], risks: list[Risk], opportunities: list[Cited], agenda: list[Cited] }
```

`refs` may be empty when the model cannot point to a line. Indices outside the transcript range are dropped server-side before saving.

### Transcript numbering

A shared helper `app/services/transcript_text.py` turns the utterance list into prompt text, one line per utterance: `[12] Ravi: text`. The index is the position in the transcript ordered by `timestamp_ms`, which is the same order the transcript endpoint returns, so frontend and backend agree on indices without storing them.

### Generators

`mom_generator.py`, `insight_generator.py`, `strategy_generator.py` keep their names and their content guidance but return `Minutes`, `Insights`, `Strategy` via LangChain structured output (`llm.with_structured_output(Model)`), with the same provider switch in `llm_config.py`. Each prompt receives the numbered transcript and the participant list, and asks for `refs` on every item. Temperatures stay as they are. Generator errors raise; they are never stored as text.

### Storage

The outputs table gains a column `format VARCHAR(10) NOT NULL DEFAULT 'markdown'`, added by `init_saarai_tables` with `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`. New rows store `content` as JSON text with `format = 'json'`. Existing rows are untouched and remain `markdown`.

### Endpoints

- `GET /meetings/{bot_id}/outputs` returns `{ bot_id, has_outputs, outputs: { mom?: Output, insights?: Output, strategy?: Output } }` where `Output = { format: "json" | "markdown", content: object | string, created_at }`. `has_outputs` is true when at least one json row exists.
- `POST /generate/mom|insights|strategy/{bot_id}` unchanged in shape but return the structured object under `content` with `format: "json"`.
- `POST /generate/all/{bot_id}` runs the three generators in order, saving after each, and returns `{ bot_id, done: ["mom", ...], failed: { strategy?: "message" } }` with 200 when at least one succeeded and 502 when all failed.
- `GET /generate/status/{bot_id}` returns `{ running: bool, done: ["mom", ...] }`. `running` comes from an in-process per-bot lock; `done` lists json rows present.
- Any generate call while the bot's lock is held returns 409 `{ detail: "Generation already running" }`.
- The lock is a module-level dict keyed by bot id, cleared in a `finally`. It is per process; the API runs as one uvicorn worker in development, and the 409 is a cost guard, not a correctness guarantee.
- `GET /meetings/{bot_id}` also returns `transcription_state` from the recording row, which the fetcher already selects.

## Frontend

### Routes

- `meetings/:botId` is the workspace.
- `meetings/:botId/transcript` redirects to `meetings/:botId?transcript=open`.

### Data: `useMeeting(botId)` (`src/hooks/useMeeting.ts`)

Owns every fetch for the page and returns one value:

```
MeetingView {
  meeting: Meeting | null
  participants: Participant[]
  utterances: IndexedUtterance[]          // Utterance plus index
  essence: { mom: SectionState, insights: SectionState, strategy: SectionState }
  phase: "loading" | "live" | "processing" | "generating" | "ready" | "failed" | "notfound"
  error: string | null
  regenerate(section): Promise<void>
  retry(): void
}
SectionState = { status: "empty" | "generating" | "ready" | "legacy" | "error", data?: Minutes|Insights|Strategy, markdown?: string, createdAt?: string, error?: string }
```

Phase rules, from the bot state in `src/lib/status.ts`:

- `live` for thread states `joined` and `recording`: poll detail and transcript every 5 seconds.
- `processing` for `transcribing`: poll detail every 5 seconds.
- `failed` for `failed`.
- At `ready` with no json output: call `generateApi.all` once (ignore 409), set `generating`, poll `generate/status` every 3 seconds, and refetch outputs as sections complete. When `running` is false, stop; any section still missing shows `error`.
- At `ready` with json outputs: `ready`.
- Polling stops on unmount and when the tab is hidden (`document.visibilityState`), resuming on return.

`regenerate(section)` calls the per-type endpoint, marks that section `generating`, and refetches outputs on completion.

### Page layout (`src/pages/MeetingDetail.tsx`)

Header: h1 meeting name; a meta line with the date, duration derived from the last utterance's `timestamp_ms + duration_ms`, and participant chips with the host in gold; then a large Thread. The page publishes `{ name, threadState, label }` to a `MeetingContext` that TopBar reads to render the same Thread in its centre slot and the breadcrumb as "Meetings / {name}".

Essence column: `max-w-[720px]`. A sticky `SectionNav` with Minutes, Insights, Strategy as anchor links, and a Regenerate menu (per section, disabled while generating). Sections render in order:

- `MinutesSection`: summary paragraph; Decisions as a gold-dot list; Actions as a table with columns Action, Owner (chip with initial), Due, and a citation column; Discussion and Notes as plain lists.
- `InsightsSection`: Participation as one row per person with a horizontal bar sized by `share` and the note; Themes, Patterns, Concerns as lists; Sentiment as the word in the matching colour (cyan positive, ink-2 neutral, gold tense) with its note; Takeaways as a list.
- `StrategySection`: Priorities as a numbered list with owner chip and why; Risks as a table with Likelihood and Impact as text; Follow-ups, Resources, Opportunities, Agenda as lists.

Every list item and table row ends with a `Citation` chip: the timestamp of the first ref formatted `m:ss`, plus "+N" when more refs exist. Items with no refs have no chip.

`SectionState` rendering: `generating` shows the section heading with three Skeleton lines; `legacy` renders the markdown as today inside the section with a one-line notice and a "Regenerate for citations" button; `error` shows an ErrorNotice with "Try again" calling `regenerate`; `empty` (live or processing phases) is not rendered; instead the column shows one EmptyState, Devanagari `प्रतीक्षा`, title "Essence arrives when the call ends", body naming the current phase.

Transcript drawer (`src/components/meeting/TranscriptDrawer.tsx`): 360px wide on `lg` and up, docked right of the essence column, full-screen sheet below `lg`. Header with "Transcript · N lines", a find box that filters utterances by text, and a close button. Body is `TranscriptList`: utterances grouped by consecutive speaker, speaker name in cyan, timestamp in the gutter, text wrapping with Hindi and English mixed. Open state lives in the URL (`?transcript=open`) so links and refresh keep it. In `live` phase it opens by default and auto-follows the newest utterance until the user scrolls up, when a "Jump to latest" button appears.

Citation click: opens the drawer if closed, scrolls the utterance into view centred, applies a gold highlight that fades over 1.5 seconds (no animation under reduced motion, the highlight simply shows then clears).

Failed phase: the Thread's current marker in danger colour, an ErrorNotice "The bot could not complete this meeting" with any transcript still shown, no essence.

### Dashboard (`src/pages/Dashboard.tsx`)

Title is the time-of-day greeting; subtitle is the date. Three blocks:

- **Send a bot**: one row with meeting URL, bot name, "Send bot". On success the new bot appears in Live now; no banner. Errors via ErrorNotice.
- **Live now**: one row per live bot: name, card-size `StatusThread`, elapsed time since `created_at`, and the row links to the workspace. Hidden when empty. Polls `botsStatus` every 10 seconds, pausing when the tab is hidden.
- **Recent**: the last five finished meetings as rows: name, date, and a teaser that is the first decision from Minutes when a json output exists, otherwise "Essence pending". A "All meetings" link at the end. Teasers come from a new `GET /meetings/recent?limit=5` that joins the outputs table and returns `{ meeting, teaser: string | null }[]`, so the Dashboard makes two calls, not six.

### Meetings list (`src/pages/Meetings.tsx`)

Keeps search, status filter, sort, pagination, and the table. Changes: rows are links to the workspace (the whole row, keyboard focusable), the Details and Open essence buttons are removed; live meetings sort to the top within any sort; the status filter's labels come from the status map; list errors render an ErrorNotice with retry instead of an empty state; the `?q=` sync stays.

### Shared components (`src/components/meeting/`)

`StatusThread` (Thread plus visible label, label `aria-hidden`), `Citation`, `OwnerChip`, `ParticipantChips`, `SectionNav`, `MinutesSection`, `InsightsSection`, `StrategySection`, `LegacyMarkdown`, `TranscriptDrawer`, `TranscriptList`. `LinkButton` in `src/components/ui/` replaces the duplicated link-class constants in Home, Dashboard, and Meetings.

### Status map (`src/lib/status.ts`)

Full Attendee coverage: 1 "Ready to join", 2 "Joining", 8 "In waiting room", 11 "Scheduled", 12 "Staged" at `joined`; 3 "In meeting", 4 "Recording", 13 "Recording paused", 14 "Joining breakout room", 15 "Leaving breakout room", 16 "Recording permission denied" at `recording`; 5 "Leaving", 6 "Transcribing" at `transcribing`; 9 "Essence ready" and 10 "Deleted" at `ready`; 7 "Failed" at the new `failed` thread state. Unknown codes stay `joined` "Unavailable". `isLiveState` covers 3, 4, 13, 14, 15, 16. `Thread` renders `failed` with the current marker at the Recording position in `--danger` and the steps after it hollow; the step label under it reads "Failed".

### Types (`src/api.ts`)

`Minutes`, `Insights`, `Strategy`, `Cited`, `Action`, `Participation`, `Priority`, `Risk`, `Sentiment`, `Output`, `OutputsResponse`, `GenerateStatus`, `RecentMeeting` mirror the backend schemas. `generateApi` gains `mom`, `insights`, `strategy`, `status`. `meetingsApi` gains `recent`. `Meeting` gains `transcription_state?: number`.

### Leftovers from sub-project 1 fixed here

Corner mesh at 200px and 25 percent opacity below 768px. The duplicated status snippet and link-class constants are removed by the shared components above. Meetings no longer swallows API errors.

## Accessibility

Citations are buttons with an accessible name "Show source at m:ss". The drawer is a `dialog` on mobile with focus trapped and Escape to close, and a `complementary` region on desktop. The highlighted utterance gets `aria-current="true"`. Tables have header cells. The participation bar has a text percentage. The live auto-follow announces nothing; the "Jump to latest" button is the only live-region-free affordance.

## Testing

Backend (pytest, new `saar_ai/tests/`): schema validation including ref clamping; transcript numbering order; generators with a fake structured LLM; the lock returning 409 and clearing after failure; `all` saving partial results; outputs returning both formats; the recent endpoint's teaser.

Frontend (Vitest): status map coverage for every code; `useMeeting` phase transitions with fake timers and a mocked client (live to processing to generating to ready; failed; legacy; 409 ignored); each section renders its schema; citation click opens the drawer and marks the utterance current; transcript redirect; Dashboard live and recent blocks including "Essence pending"; Meetings row link, live-first sort, and error state; `LinkButton`.

Manual: one real meeting end to end (send bot, watch live transcript, see generation, read essence, click citations) in both themes at 1280px and 375px.

## Out of scope

- Automatic generation when the call ends (needs webhooks; roadmap).
- Chat over a meeting and Settings persistence (sub-project 3).
- Word-level highlighting in the transcript.
- Editing the essence.
